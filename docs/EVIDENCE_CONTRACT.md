# Evidence Contract｜证据契约

DealScope 的核心约束是：**检索成功不等于事实成立，模型输出不等于原文证据，分数不等于投资结论。**

## 状态模型

| 状态 | 系统已知 | 系统仍未知 | 评分处理 |
|---|---|---|---|
| 线索 | 某搜索后端返回了标题、摘要或 URL | 原文、日期、主体、语义均可能不可靠 | 不进入正式评分 |
| 已读原文 | 已保存正文、最终 URL 和采集元数据 | 事实是否指向目标主体 | 可进入后续验证，不自动加分 |
| 引文匹配 | 引文可在正文中逐字定位 | 引文是否足以支持更宽泛的推断 | 只支持引文覆盖的具体事实 |
| 主体匹配 | 引文明确指向目标公司或法定主体 | 是否存在同名、关联主体或媒体转述 | 允许进入对应维度 |
| 独立确认 | 不同原始来源支持同一项具体事实 | 来源是否共享同一上游稿件 | 提高置信度，但不重复累计事实 |
| 人工复核 | 人工核对日期、主体、语义与材料用途 | 后续尽调未知项 | 可进入正式研究材料 |

## 日期规则

优先级为：

1. 明确的事件发生日；
2. 原文发布日期，并明确标注“以发布日期代替事件日”；
3. 缺少以上日期时保持未知。

抓取时间、导入时间、文件修改时间和搜索发现时间均不得替代事件或发布日期。未来日期也不会产生“近期”加分。

## 独立确认规则

- 同一 URL 被多个查询命中：一条来源。
- 同一文章被多个搜索提供方返回：一条来源。
- 媒体转载同一新闻稿：默认不是独立确认。
- 公司公告与客户公告分别确认同一合同：可能构成独立确认，仍需人工复核。
- 只有对同一具体主张的支持才能计为交叉确认，泛行业观点不能替代项目事实。

## 抽取失败

当 LLM、CLI、网页读取或解析失败时：

- 保留结构化诊断和失败原因；
- 不用启发式“补写”正向事实；
- 不伪造引文；
- 不覆盖上一次成功报告；
- 允许用户补充原文后重试。

## 评分边界

结构化评分用于比较“当前证据下的跟进优先级”，不是公司内在价值、融资成功概率或投资收益预测。任何维度都必须能回指支持证据、缺失信息和适用门禁。
